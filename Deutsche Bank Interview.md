**What is a database index, and how are indexes created?**
A database index is a data structure that improves the speed of data retrieval operations on a table by allowing quick access to rows based on specific columns. It functions like a lookup table, helping the database avoid full table scans during queries, thus speeding up searches, joins, and sorting operations. Indexes are typically created using the `CREATE INDEX` statement in SQL and can be built on one or more columns. While they enhance query performance, indexes also consume additional disk space and can slow down write operations (e.g., `INSERT`, `UPDATE`, `DELETE`), as the index must be updated with each change.
An index acts like a "cache" for specific columns of a table, allowing the database to quickly find and retrieve data without scanning the entire table. It stores a sorted copy of the indexed columns along with pointers to the actual rows, enabling faster lookup, sorting, and filtering operations. However, unlike traditional caching, indexes are stored on disk and are automatically updated when the data in the table changes.

**What is an SQL join? Name three different kinds and explain when to use them.**
An SQL join is a technique used to combine records from two or more tables in a database based on a related column between them. This helps retrieve meaningful data from multiple tables that are connected via relationships, like foreign keys.
An INNER JOIN is used to retrieve records that have matching values in both tables. It only returns rows where there is a match between the joined tables, excluding rows that don't have corresponding entries. This join is ideal when you need to focus on related data from both tables. A LEFT JOIN (or LEFT OUTER JOIN) returns all records from the left table and the matching records from the right table. If there’s no match in the right table, the result will contain `NULL` values for the right table's columns, making it useful when you want to ensure no data from the left table is omitted. In contrast, a RIGHT JOIN (or RIGHT OUTER JOIN) is similar to a LEFT JOIN but returns all records from the right table, with matching records from the left. If no match is found in the left table, the result will contain `NULL` for the left table’s columns, ensuring no data from the right table is excluded. These joins help in extracting data from tables based on how they are related and how you want unmatched data to be handled.

**What is a linked list? How do you create, insert, delete, and traverse it?**
A linked list is a dynamic data structure that represents a sequence of elements, where each element (node) contains two fields: one storing the actual data and another storing a reference (or pointer) to the next node in the list. Unlike arrays, linked lists do not require contiguous memory allocation, allowing for efficient insertions and deletions without the need for resizing or shifting elements. However, this comes at the cost of losing direct access to elements, as traversal must be done sequentially.
To create a linked list, you define a node structure containing the data and a reference to the next node. The head pointer keeps track of the first element, enabling traversal of the entire list.
To insert an element, typically at the end for efficiency, you update the current tail node’s reference to point to the new node and then update the tail pointer.
To delete an element, you adjust the reference of the previous node to skip over the target node (i.e., point to `next.next`). Once a node is unlinked from the list, Java’s garbage collector (GC) automatically reclaims its memory.
Traversing a linked list is done by starting at the head and following the references until reaching the end (where the next reference is `null`).
This structure is particularly useful when frequent insertions and deletions are required, as it avoids the overhead of resizing an array or requiring large blocks of contiguous memory.

**How does a HashMap work, and how is it implemented?**

The load factor in a `HashMap` determines when the underlying array (bucket structure) should be resized to maintain efficient performance. It is the ratio of the number of stored entries (size) to the total number of available buckets (capacity).

**What is the difference between breadth-first search (BFS) and depth-first search (DFS)?**
Breadth-first search (BFS) and depth-first search (DFS) are both traversal algorithms used to explore graphs and trees. The main difference lies in how they explore unvisited nodes.
- BFS (Breadth-first Search) explores nodes level by level. It starts at a given node, explores all of its neighbors first, then moves on to the neighbors of those neighbors, and so on. This ensures that the algorithm visits all nodes at distance `k` before visiting nodes at distance `k+1`. BFS typically uses a queue to store the frontier (the nodes to be visited next). You enqueue the starting node, then dequeue a node, exploring its neighbors by adding them to the queue. This continues until the queue is empty.
	- example: Imagine you need to move from the top-left corner to the bottom-right corner of a grid, where each cell is either open or blocked. You can only move up, down, left, or right. BFS explores all possible moves level by level, ensuring you find the shortest path to the destination.
- DFS (Depth-first Search) explores nodes by diving as deep as possible into a branch before backtracking. It starts at the root node and explores a node’s first unvisited neighbor, continues to explore deeper into the graph, and only backtracks once a node has no unvisited neighbors. DFS typically uses a stack (or recursion, which uses the call stack) to store the frontier. The algorithm continues down a single path until no further nodes can be explored, and then it backtracks to explore new paths.
	- example: Check if a path from a node `a` to a node `b` exists in a graph. DFS explores deeply along a path until it reaches a dead end, then backtracks to try other paths.

**Explain dynamic programming and provide an example.**
Dynamic Programming is a technique to avoid redundant computations on a problem that has a perfect sub-structural nature. This means that the problem can be solved by the combination of the results of subproblems and that we have overlapping, meaning that subproblems share sub-sub-problems. 
DP exploit this by storing previous results to avoid repeating computations. 
An example is the fibonacci series. To compute the n-th fibonacci number we have to compute the sum of the (n-1)th number and the (n-2)th number. 
But to compute the (n-1)th number we have to compute the (n-2)th number and the (n-3) number, and to compute the (n-2)th number we have to compute the (n-3)th number and (n-4)th number. 
We do not want to compute more than once the (n-2)th and (n-3) number, for example. 
Dynamic programming use either memoization or tabulation: 
- memoization, top down approach: whenever we compute a fibonacci number we store it in an array. When we need a fibonacci number we check whether is present in the array, if not compute it and store it, otherwise reuse it
- tabulation, bottom-up approach, simply fill an array with every fibonacci number and reuse overlapping numbers

```java
// memoization
int fibonacci(int n, int[] dp) {
	if (n == 0)
		return 0; 
	if (n == 1)
		return 1; 

	if (dp[n] == -1)
		dp[n] = fibonacci(n-1, dp) + fibonacci(n-2, dp);

	 return dp[n-1];
}

// tabulation
int fibonacci(int n) {
	int dp[] = new int[n]; 
	dp[0] = 0; 
	dp[1] = 1;

	for (int i = 2; i < n; i++) 
		dp[i] = dp[i-1] + dp[i-2];

	return dp[n-1];
}
```

**Explain different implementations of the Singleton pattern with multithreading considerations.**
The Singleton pattern ensures a class has only one instance and provides a global point of access to it. In a multithreaded environment, different approaches can be used to ensure thread-safety. **Eager initialization** creates the instance when the class is loaded, ensuring thread-safety without synchronization, but it may create the instance even if it’s never used. **Lazy initialization** creates the instance only when needed, but is not thread-safe by default. To address this, **lazy initialization with synchronization** ensures thread-safety by synchronizing the `getInstance()` method, though it introduces performance overhead. **Double-checked locking** reduces synchronization overhead by only locking the instance creation code, improving efficiency. The **Bill Pugh Singleton** uses a static inner class to lazily initialize the instance in a thread-safe manner, relying on the Java class loading mechanism. Finally, the **Enum Singleton** is the simplest and most effective approach, ensuring thread-safety and handling serialization automatically. Among these, the Bill Pugh and Enum approaches are considered the most efficient and reliable for thread-safe Singleton implementations.

**Double-checked locking** is a technique used in the Singleton pattern to improve performance by reducing the overhead of synchronization. It ensures thread-safety while minimizing the performance cost that comes with using synchronization in every call to the `getInstance()` method.
In a multithreaded environment, multiple threads might attempt to create the Singleton instance at the same time, potentially resulting in multiple instances. To prevent this, synchronization is used. However, synchronizing the entire `getInstance()` method can be inefficient because it forces every thread to wait, even when the instance has already been created.
```java
public class Singleton {
    private static volatile Singleton instance;
    private Singleton() {}
    public static Singleton getInstance() {
        if (instance == null) {  // First check (outside synchronization)
            synchronized (Singleton.class) {
                if (instance == null) {  // Second check (inside synchronization)
                    instance = new Singleton(); // Instance is created here
                }
            }
        }
        return instance;
    }
}
```

The **Bill Pugh Singleton** is a highly efficient and thread-safe way to implement the Singleton pattern, utilizing a **static inner class**. This approach leverages the **Java class loading mechanism** to ensure that the Singleton instance is created lazily and in a thread-safe manner, without needing explicit synchronization.
The `SingletonHelper` inner class is loaded only when the `getInstance()` method is called for the first time. This ensures that the instance is created only when it is needed, and because the inner class is loaded lazily, it's also thread-safe by default. The JVM guarantees that the instance of the inner class is created only once, even in multithreaded environments, and class initialization happens only once, ensuring efficient performance.

**How would you sum two numbers without using the `+` operator?**
To sum two numbers without using the `+` operator, you can use bitwise operations. Specifically, the XOR (`^`) operator can be used to add the two numbers without considering any carry. The AND (`&`) operator, followed by a left shift (`<<`), is used to calculate the carry. The XOR operation gives the partial sum by adding bits where there is no carry, and the AND operation followed by a left shift computes the carry, which is then added to the sum in the next iteration. This process continues until there is no carry left. 
This method simulates the binary addition process and works efficiently without directly using the `+` operator. The time complexity is $O(\log(\max(a, b)))$ due to the bitwise operations, and the space complexity is O(1), as only a few variables are used for computation.

```java
public static int add(int a, int b) {
        // Continue until there is no carry
        while (b != 0) {
            // Carry now contains common set bits of a and b
            int carry = a & b;

            // Sum without carry
            a = a ^ b;

            // Carry is shifted by one so that adding
            // it to a gives the required sum
            b = carry << 1;
        }
        return a; // The result is stored in a
    }
```

**Write a sorting algorithm of your choice and discuss its time complexity.**
Merge Sort has a time complexity of $O(n\log⁡n)$, where $n$ is the length of the array. This is due to the algorithm's recursive nature, which divides the array into two halves at each step, resulting in $O(\log⁡n)$ levels of recursion. At each level, the merging process takes $O(n)$ time to combine the two sorted halves. As a result, the overall time complexity is $O(n\log⁡n)$. The space complexity is $O(n)$, as the algorithm requires additional space for the left and right subarrays during the merge process. This space is used to store temporary arrays created at each recursive step, making the space complexity linear with respect to the size of the input array.
```java
public void mergeSort(int[] array) {
	if (array.length < 2) 
		return;  // Base case: single element is already sorted

	// Split the array into two halves
	int mid = array.length / 2;
	int[] left = new int[mid];
	int[] right = new int[array.length - mid];

	// Copy data into left and right arrays
	// source array, where to start the copy, where to put it, from where, 
	// what size
	System.arraycopy(array, 0, left, 0, mid);
	System.arraycopy(array, mid, right, 0, array.length - mid);

	// Recursively sort both halves
	mergeSort(left);
	mergeSort(right);

	// Merge the sorted halves back into the original array
	merge(array, left, right);
}

public static void merge(int[] array, int[] left, int[] right) {
	int i = 0, j = 0, k = 0;

	// Merge the left and right arrays into the original array
	while (i < left.length && j < right.length) {
		if (left[i] <= right[j]) {
			array[k++] = left[i++];
		} else {
			array[k++] = right[j++];
		}
	}

	// Copy any remaining elements from the left array
	while (i < left.length) {
		array[k++] = left[i++];
	}

	// Copy any remaining elements from the right array
	while (j < right.length) {
		array[k++] = right[j++];
	}
}
    
```

**Explain and write the code for Quicksort**
Quicksort is a popular and efficient sorting algorithm that follows the "divide and conquer" paradigm. It works by selecting a "pivot" element from the array, then partitioning the array into two sub-arrays, such that one sub-array contains elements less than the pivot and the other contains elements greater than the pivot. These sub-arrays are then recursively sorted.
The main steps of the algorithm are:
- Choose a pivot: The pivot can be selected in various ways, for instance, choosing the first element, the last element, or the middle element of the array.
- Partition the array: Rearrange the array such that all elements less than the pivot come before it, and all elements greater than the pivot come after it. This step ensures that the pivot is in its correct sorted position.
- Recursively sort the two sub-arrays (elements less than pivot and elements greater than pivot).
```java
public void quickSort(int[] arr, int low, int high) {
	if (low < high) {
		// Partitioning index
		int pivotIndex = partition(arr, low, high);
		
		// Recursively apply quicksort to the left and right sub-arrays
		quickSort(arr, low, pivotIndex - 1);  // Left sub-array
		quickSort(arr, pivotIndex + 1, high); // Right sub-array
	}
}

// Partition function that uses the last element as pivot
public int partition(int[] arr, int low, int high) {
	int pivot = arr[high]; // Choose the last element as pivot
	int i = low - 1; // Pointer for smaller elements
	
	for (int j = low; j < high; j++) {
		// If the current element is smaller than or equal to pivot
		if (arr[j] <= pivot) {
			i++;
			// Swap arr[i] and arr[j]
			int temp = arr[i];
			arr[i] = arr[j];
			arr[j] = temp;
		}
	}

	// Swap the pivot element with arr[i + 1]
	// to place the pivot in the correct position
	int temp = arr[i + 1];
	arr[i + 1] = pivot;
	arr[high] = temp;

	return i + 1; // Return the pivot index
}
```

Time Complexity:
- Best and Average Case: $O(n\log n)$, where n is the number of elements.
- Worst Case: $O(n²)$, which happens if the pivot selection consistently results in unbalanced partitions (for instance, if the array is already sorted).

The space complexity of the quicksort algorithm with the implementation I provided is **O(1)** for the sorting part because the sorting is done in place

In practice, Quicksort with a random pivot is preferred to avoid the worst-case scenario.

**Explain the jump game problem in dynamic programming.**
Consider an array $A$ of $n$ integers.

This means that if $A[i] = x$ then we can jump any distance $y$ such that $y \le x$. 
Find the minimum number of jumps to reach the end of the array starting from the beginning of the array. Return $-1$ if it is not possible to reach the end. 

We use an array `jumps` to store intermediate results. 
Formally `jumps[i]` is the minimum number of jumps needed to reach the position $i$ starting from the start of the array. 

The solution is in the following snippet: 
```java

	jumps[n]
	// before starting the only reachable position
	// is the starting position, which requires 0 jumps.

				jumps[i] = Math.min(jumps[i], jumps[j] + 1)
				break

	return jumps[n-1]
```

The key is the **if** guard inside the two loops: 
- `j + A[j] >= i`: we want to reach the position `i` and we are currently in the position `j`. If `j + A[j] >= i` it means that from `j`, plus the length of the jump we can make from `j` (`A[j]`), we can actually reach `i`
- `jumps[j] != MAX`: we can actually reach the position `j` from the start of the array

**Then** the minimum number of jumps required to reach `i` is the minimum between the current minimum number of jumps to reach `i` (`jumps[i]`) and the jumps required to reach `j` plus the one jump to reach `i` (`jumps[j] + 1`).

**Write a program to rotate a singly linked list of length n of k position to the right**
Set `k = k % n` as this handles the cases where k > n (which means that the rotation will make the list equal as before and then rotate some more). 
At this point make the list a circular list, set tail.next = head. 
Then we simply start from the head and iterate `k` times, every time moving to the next element. 
At this point, the head will be the next element of the reached element, and the current element.next will be set to null.

```java 

public void rotate(Node head, int k) {

	Node tmp = head; 
	int size = 1;
	while (tmp.next != null) {
		tmp = tmp.next; 
		size++;
	}

	k = k % size; 
	tmp.next = head; // make the list circular
	tmp = head; 
	for (int i = 0; i < k; i++)
		tmp = tmp.next; 

	head = tmp.next;
	tmp.next = null;
}
```

**What are the five SOLID principles of object-oriented programming?**
The **SOLID** principles are five fundamental design principles in object-oriented programming that help create maintainable, scalable, and robust software. They are:
1. **Single Responsibility Principle (SRP)** – A class should have only one reason to change, meaning it should have only one responsibility. This ensures better maintainability and reduces unintended side effects when modifying code.
2. **Open/Closed Principle (OCP)** – Software entities (classes, modules, functions) should be open for extension but closed for modification. This means new functionality should be added by extending existing code rather than modifying it, promoting flexibility and scalability.
3. **Liskov Substitution Principle (LSP)** – Subtypes should be substitutable for their base types without altering the correctness of the program. This ensures that derived classes extend the base class without changing its behavior.
4. **Interface Segregation Principle (ISP)** – A class should not be forced to implement interfaces it does not use. Instead of having large, general-purpose interfaces, smaller and more specific ones should be created to improve modularity.
5. **Dependency Inversion Principle (DIP)** – High-level modules should not depend on low-level modules; both should depend on abstractions. This encourages the use of dependency injection and reduces tight coupling between components, improving code flexibility and testability.

**How do you handle race conditions and deadlocks in multithreading?**
Race conditions occur when multiple threads access shared resources concurrently, and the outcome depends on the order in which threads execute. To handle race conditions, synchronization mechanisms are crucial. In Java, for example, the `synchronized` keyword ensures that only one thread can execute a critical section of code at a time, providing mutual exclusion. Thread-safe collections (like `ConcurrentHashMap`), can also be used to avoid race conditions and ensure safe access to shared resources.

There are algorithms like the Banker's Algorithm or techniques such as timeout and resource ordering (a proper resource acquisition order and ensuring that threads don’t acquire resources in a circular manner) can be used to avoid deadlocks. Also minimize the scope of locks, use finer-grained locking, or utilize higher-level abstractions like `ExecutorService` to manage thread pools and tasks more effectively can help you avoid deadlock.

Once a deadlock occurs and no time limits or preemptive mechanisms are in place, it becomes challenging to break the deadlock automatically. In such cases, intervention is required, typically through manual actions or system-level recovery techniques. One approach is to **terminate** one or more processes involved in the deadlock, which releases their resources and allows other processes to proceed. Alternatively, **resource preemption** can be used to forcibly reclaim resources from one process and assign them to another, breaking the circular wait. Another strategy is to **rollback** processes to a previous state, releasing their resources and allowing execution to resume. However, the best approach is to design the system to **prevent deadlocks** through methods like resource ordering, timeouts, or careful synchronization in the first place.

**What is the difference between call-by-value and call-by-reference?**
The difference between call-by-value and call-by-reference lies in how function arguments are passed. In call-by-value, a copy of the actual argument’s value is passed to the function, meaning any changes made inside the function do not affect the original variable outside of it. Java uses call-by-value for all method arguments, but with objects, it passes the reference (memory address) to the object by value, not the reference itself. This means that while changes to the object's internal state will affect the original object, reassigning the reference itself (i.e., pointing it to a new object) will not. On the other hand, call-by-reference passes the actual reference to the argument, allowing modifications to both the data and the reference itself. While C++ supports true call-by-reference, Java does not, as it always uses call-by-value, even for objects, which often leads to the misunderstanding that Java uses call-by-reference.

**What is the difference between pointers in C/C++ and Java’s reference mechanism?**
Pointers in C++ and references in Java both provide ways to access memory, but they differ significantly in functionality and safety. C++ pointers store memory addresses and allow direct manipulation, including arithmetic operations, making them powerful but prone to issues like memory leaks and dangling pointers if not managed properly. In contrast, Java references are safer and always point to objects, with memory management handled automatically by the Garbage Collector, eliminating the need for manual deallocation. Unlike pointers, Java references do not support pointer arithmetic, reducing the risk of memory corruption. While C++ pointers offer greater control for low-level programming, Java’s reference mechanism prioritizes safety and ease of use.

**How does the binary left shift operator work in C and Java?**
The binary left shift operator (`<<`) in both C and Java shifts the bits of a number to the left by a specified number of positions, filling the empty positions with zeros on the right. This operation effectively multiplies the number by $2^n$, where $n$ is the number of positions the bits are shifted. In C, the behavior depends on the size of the data type, and shifting beyond the number of bits in the type (e.g., shifting an `int` more than 31 positions) results in undefined behavior. In Java, the left shift works similarly but is constrained by the bit-width of the data type (32 bits for `int` and 64 bits for `long`). If the shift count exceeds the bit width, the result is equivalent to shifting by the remainder (e.g., shifting an `int` more than 31 bits will shift by `n % 32`). In both languages, the shift operation increases the value of the number unless shifting zeros into the leftmost bit of signed types.

**What happens if you define the `hashCode` as a single constant in an object class?**
Defining the `hashCode` method as a single constant in an object class means that all instances of that class will return the same hash code. This leads to incorrect behavior in hash-based collections like `HashMap` and `HashSet`. Since these collections rely on the `hashCode` method to distribute objects into different buckets, using a constant hash code causes all objects to be placed in the same bucket.
For a `HashMap`, this would mean that only the last inserted object would be retained, because adding a new key with the same hash code would overwrite the previous key-value pair. For a `HashSet`, only the first inserted object would be stored, as subsequent objects with the same hash code would be treated as duplicates.
Additionally, using a constant `hashCode` violates the general contract of `hashCode`, which specifies that distinct objects should ideally have different hash codes for optimal performance. While this approach might be acceptable for cases like immutable singleton classes, it is generally considered bad practice and should be avoided in typical use cases.

**What is segregation and aggregation in OOP?**

Aggregation implies a looser coupling than composition, where the contained objects' lifetimes are tied to the parent object. Together, these concepts help create more modular, flexible, and maintainable systems in OOP.

**What happens when creating a new instance of a generic type parameter?**
In Java, when creating a new instance of a generic type parameter, you cannot directly instantiate the generic type due to **type erasure**. Type erasure removes the specific type information at runtime, replacing the generic type with `Object` or a bounded type (e.g., `T extends SomeClass`). This means you can't simply use `new T()` inside a generic class. To work around this, you typically use reflection, where you pass the `Class<T>` object to the constructor and use it to instantiate the type. Alternatively, if the generic type has a bound (e.g., `T extends SomeClass`), you may be able to instantiate the type if `SomeClass` has a default constructor. Thus, direct instantiation is not possible, and reflection or bounded types are used to handle generic type instantiation.

```java
import java.lang.reflect.Constructor;

public class Box<T> {
    private T item;

    // Constructor accepts Class<T> to use reflection for instantiating T
    public Box(Class<T> clazz) {
        try {
            // Use reflection to create an instance of T
            Constructor<T> constructor = clazz.getDeclaredConstructor();
             // Instantiate T using the constructor
            this.item = constructor.newInstance();
        } catch (Exception e) {
            e.printStackTrace();
        }
    }

    public T getItem() {
        return item;
    }

    public static void main(String[] args) {
        // Create a Box instance with Integer type using reflection
        Box<Integer> integerBox = new Box<>(Integer.class);
		// Outputs: Item in the box: 0
        System.out.println("Item in the box: " + integerBox.getItem()); 

        // Create a Box instance with String type using reflection
        Box<String> stringBox = new Box<>(String.class);
        // Outputs: Item in the box: null
        System.out.println("Item in the box: " + stringBox.getItem()); 
    }
}

```
